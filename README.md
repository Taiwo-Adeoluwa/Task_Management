# Task Management API

A RESTful Task Management API built with **Node.js, Express.js, MongoDB, and Mongoose**.

The application provides CRUD functionality for managing tasks, including creating, retrieving, updating, and deleting tasks. It also includes request validation using **Joi**, MongoDB persistence using **Mongoose**, HTTP request logging with **Morgan**, CORS support, and environment-based configuration.

This project was built to demonstrate practical understanding of backend web development, RESTful API design, middleware, database integration, validation, and error handling.

---

## Features

- Create a task
- Retrieve all tasks
- Retrieve a single task by ID
- Update a task
- Delete a task
- Request body validation using Joi
- MongoDB database persistence
- Mongoose schema validation
- Automatic `createdAt` and `updatedAt` timestamps
- Error handling for missing resources
- HTTP request logging with Morgan
- CORS support
- Environment variable configuration
- RESTful API architecture

## How the Application Works

The application follows a simple backend request flow:

Client / Postman
       ↓
Express Server
       ↓
     Route
       ↓
Validation Middleware
       ↓
   Controller
       ↓
    Mongoose
       ↓
   MongoDB
       ↓
  JSON Response

For example, when a client creates a task:

- The client sends a POST request.
- Express receives the request.
- The request passes through the Joi validation middleware.
- The controller receives the validated data.
- Mongoose creates the task in MongoDB.
- The API returns a JSON response to the client.  

## Task Structure

Each task contains the following fields:
 
Field	           Type	           Required	                   Description
title	           String	        Yes	                       Title of the task
description	       String	        Yes	                       Description of the task
status	           String	        No	                       Current status of the task
dueDate	           Date	            Yes	                       Date the task is due
createdAt	       Date	          Automatically generated	   Task creation date
updatedAt	       Date	          Automatically generated	   Last update date

## Task Status

The available task statuses are:

- pending
- in progress
- completed

The default status is: pending

The createdAt and updatedAt fields are automatically generated by Mongoose using schema timestamps.

## Validation

The API uses Joi to validate incoming task data before it reaches the controller.

For example, a task requires:

- title
- description
- dueDate

The status field accepts only:

pending
in progress
completed

Invalid requests return a 400 Bad Request response.

Example of Validation Response:
{
  "success": false,
  "message": [
    "Title is required",
    "Description is required"
  ]
}

** Unknown fields are removed from the request using Joi's stripUnknown option.

## Error Handling

The API returns appropriate HTTP status codes for different situations.

Status Code         	Meaning
200	                    Request successful
201	                    Task created successfully
400	                    Invalid request or validation error
404	                    Task not found
500	                    Internal server error

Example: Task Not Found
{
  "success": false,
  "message": "Task not found"
}
